# 배틀팩토리

레이팅 / AI 대전과 나란히 배틀 선택 화면에서 입장한다. 보유 포켓몬 팀이 없어도 도전할 수 있다.

## 진행 규칙

1. 매 도전마다 랜덤으로 제시되는 렌탈 포켓몬 6마리 중 서로 다른 3마리를 선택한다.
2. 준비 화면에서 상대 팀을 확인하고 아군 3마리 중 선봉 1마리를 직접 선택한다. 선봉을 선택해야 배틀 시작 버튼이 활성화되며, 시작 전까지 변경할 수 있다. 1층부터 시작해 랜덤 상대 3마리와 Lv.50 싱글 3대3 배틀을 한다. 기존 AI 배틀 엔진, 보통 난이도, 맑음, 일반 필드를 사용한다. 기술·특성·도구·교체·배틀 기믹도 기존 엔진의 규칙을 따른다.
3. 승리 결과의 **배틀 마치기**를 누르면 교환 화면으로 이동한다. 바로 이전 상대의 포켓몬 3마리 중 1마리를 현재 아군 1마리와 교환하거나, 교환 없이 진행한다.
4. 교환 여부와 관계없이 다음 층마다 새로운 상대 3마리를 확인하고 선봉을 다시 선택한다. 아군은 체력·PP·상태이상·소비 도구·기믹 사용 상태가 초기화된다. 교환된 포켓몬도 원래 렌탈 구성으로 들어온다.
5. 같은 도감 번호의 포켓몬은 동시에 편성할 수 없다. 교환은 층마다 최대 한 번이다. 패배·무승부·기권이면 도전이 종료되며 새로운 렌탈 후보로 다시 시작할 수 있다.

기존 트레이너 팀의 실제 포켓몬 구성에서 종을 균등하게 추첨한 뒤 해당 종의 기술·특성·도구 구성을 선택한다. 특정 트레이너의 반복 팀 때문에 같은 종의 추첨 비중이 높아지지 않는다. 상세 정보 버튼으로 도구·특성·성격·테라타입·능력치·기술을 확인할 수 있다.

층수와 연승 수는 현재 도전에 속한다. 같은 페이지에서 배틀 허브로 나갔다가 돌아오면 도전을 유지하며, 새로고침 또는 창을 닫으면 진행 중인 도전은 초기화된다. 패배·무승부·기권으로 정상 종료한 도전은 아래 랭킹에 기록한다. 렌탈 포켓몬은 계정 박스·아이템 인벤토리·VP·RP를 변경하지 않으며 AI/레이팅의 사용률에도 합산하지 않는다.

상대 트레이너는 사용자가 제공한 삐에로 PNG를 변경 없이 `public/assets/trainers/factory-clown.png`에 저장해 사용한다.

## TOP 10 랭킹

팩토리 화면 상단의 **TOP 10 랭킹**에서 확인한다. 유저마다 가장 높은 도달 층수의 기록 하나만 등록하며, 같은 층이면 서버가 먼저 등록한 기록을 우선한다. 더 낮거나 같은 개인 기록은 기존 최고 기록과 팀 구성을 덮어쓰지 않는다. 순위는 1~10위까지만 표시하고 실제 기록이 적으면 등록된 인원만 보여준다. 내 최고 기록은 10위 밖에서도 별도로 확인할 수 있다.

각 기록에는 해당 도전 마지막 배틀에 출전한 포켓몬 3마리의 구성을 고정해 저장한다. 순위를 펼치면 지닌 도구와 기술을 확인하고, 포켓몬 정보 버튼으로 특성·성격·테라타입·능력치까지 볼 수 있다. 전투 중 소비된 도구는 원래 장착했던 도구로 표시하며, 다음 도전이나 박스 편집이 이전 기록을 바꾸지 않는다. 공개 닉네임은 기존 레이팅과 같이 첫 글자와 `**`로 표시한다.

Google 계정은 기존 인증된 `/api/ranked`의 `factoryLeaderboard` 조회 및 `reportFactoryRun` 등록을 사용한다. 기존 Firestore 어댑터에 개인 최고 기록과 상위 10위 문서만 저장하며 전체 유저 문서를 스캔하거나 배틀 도중 주기적으로 랭킹을 조회하지 않는다. 화면 열기·새로고침·도전 종료 때 갱신한다. 전송 대기 기록은 계정별로 로컬에 먼저 저장해 연결 실패 후 재시도할 수 있다.

게스트는 **이 기기 랭킹**으로 구분해 브라우저에 저장한다. 게스트 기록을 전체 유저 랭킹으로 표시하거나 자동 업로드하지 않는다. `factory:test`에서는 두 로컬 테스트 계정이 같은 파일 저장소를 사용하는 공유 랭킹까지 시험할 수 있다.

서버는 인증된 계정, 종료 결과 형식, 층수·승수의 일치, 종·도구·특성·기술·능력치의 유효성을 검사한다. 현재 AI 전투 결과는 클라이언트에서 보고하는 방식이며, 서버에서 전투 전체를 재연산하는 부정행위 방지 시스템은 포함하지 않는다.

## 로컬 실행 및 검증

```sh
npm run factory:test
npm run validate:battle-factory
npm run validate:battle-factory-ui
npm run validate:battle-factory-ranking
npm run validate:battle-factory-ranking-client
npm run build
```

수동 테스트 주소는 `http://127.0.0.1:5187`이며 두 번째 테스트 계정은 `http://127.0.0.1:5187/?trainer=b`로 연다. Firebase와 운영 API는 사용하지 않고, 8790 포트의 로컬 API가 `scripts/.cache/battle-factory-local/state.json`에 랭킹을 저장한다. 임의 순위 데이터는 넣지 않는다. 기존 사용률 테스트 서버(5186/8788)와 포트를 공유하지 않는다. 로컬 미리보기 진입 코드는 개발 서버 플러그인에서만 제공하며 운영 앱의 진입 코드를 바꾸지 않는다.

모델 검증은 시드 재현성·렌탈 합법성·선출 제한·교환/생략·중복 종·이전 결과 중복 수신·종료·다음 층 회복과 실제 배틀 엔진의 턴 및 3대3 완주를 다룬다. UI 검증의 결과 화면용 픽스처는 브라우저 테스트 응답에만 주입하며 운영 코드에 결과 변경용 인터페이스를 추가하지 않는다.

## 배포 보류

이번 작업은 `codex/battle-factory` 브랜치에 구현과 검증만 저장한다. `vercel.json`의 `git.deploymentEnabled`에서 해당 브랜치를 `false`로 설정해 Git 푸시로 인한 자동 배포도 막는다. 다른 브랜치의 배포 설정은 유지된다. 메인 병합이나 Vercel 배포 명령을 실행하지 않는다.

설정 근거: [Vercel Git deploymentEnabled 문서](https://vercel.com/docs/project-configuration/git-configuration#git.deploymentenabled).
