# 게임 전체 점검 — 2026-09-11

시작 기준은 `main`의 `6cf1187`입니다. 배틀 엔진·AI·계정 저장·업적과 보상·메뉴·모바일 UI·기술 연출과 사운드를 나누어 점검하고, 재현된 오류에 회귀 검증을 추가했습니다. 운영 계정의 저장 데이터는 변경하지 않았습니다.

아래에 기록한 자동 검증과 브라우저 검증은 최종 통과했습니다. 배틀 종합 검사는 수정 후 19개 구성 검사 전체를 다시 실행하여 19/19 통과했고, 신규 행동 선택 회귀 21개 및 껍질몬 회귀 4개를 포함한 HP 검사 15개도 통과했습니다. 업적 UI와 계정 복구 UI는 마지막 화면 수정 후 재검증했습니다. 배포용 빌드와 `git diff --check`도 통과했습니다.

## 발견하고 수정한 문제

### 계정과 저장

- 새 브라우저에서 게스트 이전 정보와 로컬 소유자 정보가 모두 없으면 두 `undefined` 값이 같다고 판단해 기존 클라우드 저장을 빈 로컬 기록으로 덮어쓸 수 있었습니다. 명시적인 이전 UID가 있는 경우만 게스트 이전으로 처리합니다.
- 클라우드 최초 로드 실패 후 게임과 업로드가 허용되어 서버 기록을 확인하기 전에 덮어쓸 수 있었습니다. 실패 시 게임 진입과 업로드를 중단하고 기록을 유지하며, 수동 재시도·네트워크 복구 재시도·로그인 화면 복귀를 제공합니다.
- 자동 저장 중 로그아웃하면 진행 중인 업로드를 기다리지 않았습니다. `flush()`는 실행 중인 저장과 추가 변경의 저장 결과를 기다리고, 성공한 경우에만 로그아웃합니다. 실패하면 게임을 유지하고 오류를 표시합니다.
- 로컬 데이터 교체 중 저장 공간 오류를 무시하거나, 읽기 오류 시 일부 키만 모아 업로드하던 경로를 수정했습니다. 교체 실패 시 이전 스냅샷 복원을 시도하고 오류를 전달하며, 읽기에 실패한 부분 데이터는 업로드하지 않습니다.
- 미동기화 기록의 충돌 판단을 기기 시계보다 마지막 서버 revision에 우선하여 수행합니다. 게스트 이전 설정을 저장하지 못하면 Google 연결을 시작하지 않습니다.

### 배틀 행동 선택

- 앵콜을 충전·반동 대기와 같은 강제 행동으로 처리해 교대를 덮어쓰고 UI가 자동으로 턴을 진행하던 문제를 수정했습니다. 앵콜은 기술 선택만 제한하며, 같은 턴에 먼저 적용된 앵콜과 적용 순서에 따른 지속 시간도 반영합니다.
- PP 소진 또는 모든 기술이 봉인된 경우 행동할 수 없던 상황에 발버둥 선택·실행·AI 판단을 연결했습니다. 싱글과 더블 모두 지원하며, 교대 선택은 유지합니다.
- 발버둥의 실제 무타입 판정, 랜덤 상대 선택, 반동, PP 미소모, Z기술·다이맥스 변환 제외와 제한 해제 상호작용을 확인했습니다. 마지막 PP로 시작한 충전 기술의 다음 턴과 반동 대기 턴에는 발버둥을 끼워 넣지 않습니다.
- 기술 메뉴에서 앵콜·사슬묶기·도발·구애 도구 등 선택 제한을 엔진과 같은 기준으로 판단하고 이유를 표시합니다.
- 껍질몬도 일반 HP 공식을 적용받아 레벨 50에서 HP 108로 생성되던 오류를 수정했습니다. 훈련·어려움 난이도의 보정·다이맥스 중에도 최대 HP 1을 유지합니다. 껍질몬으로 변신한 메타몽은 자신의 HP를 유지하는 대조 시나리오도 확인했습니다.

규칙 대조에는 Pokémon Showdown의 원본 [기술 데이터](https://github.com/smogon/pokemon-showdown/blob/master/data/moves.ts), [특성 데이터](https://github.com/smogon/pokemon-showdown/blob/master/data/abilities.ts), [포켓몬 데이터](https://github.com/smogon/pokemon-showdown/blob/master/data/pokedex.ts), [다이맥스 상태 처리](https://github.com/smogon/pokemon-showdown/blob/master/data/conditions.ts)를 참고했습니다.

## 재현 명령

프로젝트 의존성을 설치한 상태에서 실행합니다. 브라우저 검증은 `promo`에 설치된 Playwright와 Chromium을 사용합니다. React 상태 검증용 임시 렌더러 설치는 [Firebase 설정 문서](./firebase-setup.md)의 안내를 따릅니다.

```powershell
npm run validate:battle-audit
npm run validate:battle-actions-ui
npm run validate:battle-ai-decks
npm run validate:trainer-dialogues
npm run validate:pokemon-learnsets
npm run validate:draw-pool
npm run validate:test-unlocks
npm run validate:achievements
npm run validate:achievements-ui
node scripts/validateInitialHatchUi.mjs
npm run validate:account-session
node scripts/validateAuthProvider.mjs
node scripts/validateAccountSessionSync.mjs
npm run validate:account-recovery-ui
npm run validate:move-quality
npm run validate:battle-audio
npm run build
git diff --check
```

이번 실행의 상세 로그와 임시 브라우저 관찰 결과는 `scripts/.cache/full-audit/`, 신규 UI 회귀 증거는 `scripts/.cache/account-recovery-ui/` 및 `scripts/.cache/battle-action-ui/`에 보관합니다. 캐시 파일은 Git에 포함하지 않습니다. 신규 회귀 스크립트는 저장소에 포함합니다.

## 확인 한계

- 실제 운영 Google OAuth 팝업, 배포된 Firebase 규칙 및 서로 다른 실기기에서 동일 계정으로 접속하는 전체 흐름은 실제 테스트 계정으로 검증하지 않았습니다. 계정 실패와 서버 lease 경로는 로컬 모형, 동일 브라우저의 탭 잠금은 실제 Chromium으로 확인했습니다.
- 운영 도메인은 인증 전 공개 화면만 읽었습니다. 이 검사로 인증 후 클라우드 저장 성공까지 확인했다고 판단하지 않습니다.
- 브라우저 강제 종료 또는 네트워크 단절로 서버 해제 요청이 전달되지 않으면 기존 90초 lease 만료 복구가 적용됩니다. 정상 탭 닫기와 다른 탭의 재진입은 로컬 실제 브라우저에서 확인했습니다.
- 전체 실사용 기기·모든 기술/특성/도구 조합을 수동 플레이한 검사가 아니며, 이번에 검사한 범위의 결과입니다.
- 빌드는 성공했지만 Vite의 큰 번들 경고는 남습니다. 현재 주 JavaScript 번들은 약 6.81MB, gzip 약 1.08MB입니다. 이는 실행 오류는 아니며, 초기 다운로드와 저사양 기기의 파싱 비용을 줄이기 위한 분할 최적화 여지가 있습니다.
