# Egress 및 게스트 데이터 관리

## 확인한 사용량과 원인

2026-09-13 조직 Usage 화면에서 Free 플랜의 Egress는 5.044 / 5GB, DB는 0.057 / 0.5GB였다. 화면의 집계 기간은 2026-09-03~2026-10-03이다. Egress는 누적 외부 전송량이므로 저장된 계정이나 배틀을 삭제해도 이미 사용한 양이 환급되지 않는다. 요금제나 결제 설정은 변경하지 않는다.

[Supabase 공식 문서](https://supabase.com/docs/guides/platform/manage-your-usage/egress)에 따르면 PostgreSQL을 공유 연결 풀로 조회한 결과도 Shared Pooler Egress에 포함된다. 웹 브라우저로 반환하는 JSON 크기뿐 아니라 DB에서 Vercel 서버로 보내는 데이터도 줄여야 한다. Cached Egress는 별도 할당량이며 비공개 계정 조회에 남은 CDN 캐시 할당량을 단순 전용할 수 없다. 무료 한도 초과는 사용 제한 가능성이 있으므로 최적화가 이번 집계 기간의 한도를 복원하거나 향후 무료 범위를 보장하지는 않는다.

운영 데이터의 내용 대신 DB 내부 집계만 조회했다. gameData 276개 문서의 JSON 합계는 106,865,057바이트(평균 약387KB), 최대는 1,122,355바이트였다. DB의 압축 저장 크기와 외부로 반환되는 JSON 크기는 다르다. 기존 저장 처리에서는 버전과 중복 저장 여부를 확인하려고 매 저장마다 이전 문서 전체를 읽었다.

## 적용한 절감

- **계정 저장:** `compareGameData`는 PostgreSQL 안에서 payload 동일 여부를 비교하고 revision과 비교 결과만 반환한다. 저장 순서, 동일 요청 재시도, 같은 revision의 다른 내용 거부는 유지한다. 테스트에서 1MB 저장 문서의 비교 JSON 응답은 100바이트 미만이며, 이는 해당 조회의 크기이지 서비스 전체 전송량 감소율은 아니다.
- **대전방 목록:** 같은 SERIALIZABLE 트랜잭션 안의 반복 `list`는 한 번 읽은 목록을 재사용한다. 이후 예약된 수정·삭제를 합쳐 반환하며 다른 요청과 캐시를 공유하지 않는다. 로컬 10개 방×4명 구성에서는 전체 목록을 두 번 읽어 약609.9KB를 받던 중복 조회 하나를 없앤다.
- **숨겨진 탭:** 진행 중인 매칭·방·배틀이 없는 숨김 화면은 조회를 멈춘다. 진행 중인 세션은 5초 간격으로 갱신하여 매칭 임대를 유지한다. 화면을 다시 표시하면 즉시 갱신한다. 최초 조회 실패를 비활성 상태로 오인하지 않고 재시도하며, 서버의 경기 제한시간은 바꾸지 않는다.
- **게스트 삭제:** 관련 대전만 DB에서 선택하고 큰 배틀 상태·기술 선택·팀 정보를 전송하지 않는 전용 조회로 정리한다. 다른 계정의 저장 파일이나 전체 배틀 연출을 다운로드하지 않는다. 팩토리 상위 기록이 삭제되면 다음 기록으로 빈 순위를 채우며, 후보 팀 전체 대신 상위 10개만 조회한다.

## 게스트 로그아웃

명시적으로 로그아웃한 익명 게스트만 삭제한다. 단순 페이지 이동, 숨김, 창 닫기는 이 삭제 동작이 아니다. Google 계정의 로그아웃이나 게스트의 Google 계정 연결에도 적용하지 않는다.

1. 게임 화면과 자동 저장을 중단하고 진행 중 저장 및 세션 갱신을 정리한다.
2. Firebase 익명 인증과 현재 창의 세션 소유자·버전을 확인한 `/api/account`의 `deleteGuestAccount`를 호출한다.
3. 서버에서 삭제 시작을 표시해 뒤늦은 저장·매칭 요청의 재생성을 차단한다. 매칭 큐를 취소하고 진행 중 배틀은 기권 정산하며 친선방에서 철수한다. 다른 참가자의 승패·점수·VP와 대회 진행은 유지한다.
4. 게스트의 보유 포켓몬·팀·아이템·VP·업적·설정·프로필·세션·레이팅 개인 기록·팩토리 랭킹·닉네임 예약을 삭제한다. 공유된 결과는 게스트의 UID·이름·팀·상태를 제거한 `탈퇴한 게스트`로 바꾼다. 개인을 식별하지 않는 사용률 집계는 유지한다.
5. 해당 UID의 브라우저 저장·전송 대기 목록·이전용 백업을 정리하고 Firebase 익명 인증 계정도 삭제한다. 다른 계정의 기기 데이터는 지우지 않는다.

재생성 방지에는 UID와 닉네임을 포함하지 않는 해시 키의 삭제 표식만 남긴다. 과거 사용률 영수증 중 UID 연결 정보가 원래 없었던 해시 집계 기록은 익명 상태로 유지한다. 삭제가 중간에 실패하면 성공으로 처리하거나 기존 플레이를 재개하지 않고, 같은 인증으로 삭제를 재시도한다. Firebase 계정 삭제가 이미 완료된 뒤 마지막 로컬 정리가 실패한 경우에도 남은 정리를 재시도한다. 새로고침 후에도 삭제 대기 표시가 있으면 정리를 먼저 완료한다. 이미 로그아웃했던 과거 게스트를 일괄 삭제하는 작업은 수행하지 않는다.

## 검증

`node scripts/validatePostgresStore.mjs`, `node scripts/validateAccountServer.mjs`, `npm run validate:guest-deletion`, `npm run validate:ranked-polling`로 저장 비교·순서·롤백·게스트 삭제·타인 보호·재시도·폴링 동작을 확인한다. PostgreSQL 실제 연결 검증은 `POSTGRES_STORE_INTEGRATION=true`와 서버 연결 환경을 사용하며 임의 이름의 별도 validation namespace에 만든 테스트 문서만 정리한다.

배포 뒤 Usage 지표는 집계 지연이 있으므로 다음 시간대의 증가량으로 효과를 판단한다. 누적 그래프가 바로 내려가는 것을 성공 조건으로 삼지 않는다.
