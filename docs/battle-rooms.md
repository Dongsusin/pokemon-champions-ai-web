# 대전방

배틀 선택에서 **대전방**으로 들어갑니다. 게스트와 Google 사용자가 같은 방에 참가할 수 있으며, 기존 팀 1~5 중 포켓몬 6마리를 등록한 팀을 선택합니다.

- 전체 방은 최대 10개, 각 방은 2~4명이 참가합니다. 한 계정은 한 방에만 참가하며 레이팅 상대 검색이나 다른 대전과 동시에 참가할 수 없습니다.
- 방장은 토너먼트/리그전, 싱글/더블을 정하고 2명 이상일 때 대회를 시작합니다.
- 비밀번호는 선택 사항입니다. 설정하면 숫자 1~4자리만 허용하고 `0001`처럼 앞의 0도 구분합니다.
- 각 경기는 등록한 6마리에서 싱글 3마리, 더블 4마리를 순서대로 선출합니다. 첫 번째 포켓몬(더블은 첫 두 마리)이 선봉입니다.
- 3인 토너먼트는 무작위 대진의 한 명이 부전승으로 결승에 진출합니다. 리그전은 모든 참가자끼리 한 번씩 대결하며 3인 리그전의 휴식은 승리로 기록하지 않습니다.
- 리그 순위는 승점(승리 3, 무승부 1), 승리 횟수, 적은 패배 횟수 순입니다. 끝까지 같으면 공동 순위입니다. 토너먼트에서 일반 무승부는 서버 추첨으로 진출자를 정하고 대진표에 표시합니다. 양쪽 모두 시간 초과 시 두 명 모두 탈락합니다.
- 대기 중 방장이 나가면 남아 있는 참가자에게 방장을 넘깁니다. 진행 중 방을 나가면 현재 및 남은 경기에서 기권 처리합니다.
- 방 대회는 레이팅 점수, VP 보상, 기존 AI/레이팅 사용률에 반영하지 않습니다.

## 방 삭제와 대기 시간

방의 대회 전체가 끝나면 방과 참가 상태를 삭제하고 작은 최종 결과만 보여줍니다. 생성 후 10분 동안 시작하지 않은 방과, 처음 4명이 모인 후 1분 동안 시작하지 않은 방도 삭제합니다. 4명이 모인 뒤 누군가 나갔다 다시 들어와도 1분 제한은 연장되지 않습니다.

서버 시간을 기준으로 만료 여부를 판정합니다. 만료된 방은 참가하거나 시작할 수 없고, 다음 대전방 요청에서 저장된 방도 정리합니다. 모든 사용자가 접속을 종료한 동안 정리 전용 서버 작업을 계속 실행하지 않습니다. 개별 경기에는 기존 온라인 대전의 선출·행동·교체 시간 제한을 적용합니다.

비밀번호는 서버에 소금값을 사용하는 scrypt 해시로 저장하며 응답에 포함하지 않습니다. 잘못된 입력 시 방별·계정별 시도 제한을 적용합니다. 서버가 팀 보유 정보와 경기 명령을 검사하고 결과를 확정합니다.

## 대기 중 관전

자신의 경기가 먼저 끝났거나 부전승·휴식으로 기다리는 참가자는 대진표의 **관전하기**로 같은 방에서 진행 중인 다른 경기를 볼 수 있습니다. 토너먼트 탈락자도 방에 남아 있으면 관전할 수 있습니다. 선출 중인 경기에 입장하면 대기 화면을 표시하고, 선출이 끝나는 즉시 실제 배틀 화면으로 전환합니다.

관전 화면은 양쪽의 필드에 나온 포켓몬, HP 비율, 상태, 공개된 배틀 로그와 기술 연출을 보여줍니다. 미공개 포켓몬과 선출 순서, 기술 목록·PP, 장착 아이템, 특성, 사용 전 테라 타입과 행동 선택은 전달하지 않습니다. 관전자는 기술 선택·교체·기권을 할 수 없으며, 서버도 요청마다 같은 방의 대기 참가자인지 확인합니다.

**대기실로 돌아가기**로 언제든 관전을 끝낼 수 있습니다. 자신의 다음 경기가 배정되면 출전 선택으로 자동 이동하고, 관전 중인 경기가 끝나면 대진표로 돌아갑니다. 대회가 종료되면 최종 순위로 이동합니다. 관전 상태는 별도로 저장하지 않으며 페이지를 다시 열면 현재 방 상태부터 확인합니다.

## 로컬 실행과 검증

```powershell
npm run rooms:test
```

다음 주소를 서로 다른 창에서 엽니다. 실제 계정, 운영 DB, 레이팅 점수는 사용하지 않습니다.

- `http://127.0.0.1:5185/?roomPlayer=alice`
- `http://127.0.0.1:5185/?roomPlayer=bob`
- `http://127.0.0.1:5185/?roomPlayer=charlie`
- `http://127.0.0.1:5185/?roomPlayer=dave`

로컬 테스트 상태는 Git에서 제외된 `scripts/.cache/ranked-test/state.json`에 저장합니다. 종료는 Ctrl+C입니다. 테스트 계정 인증은 명시적으로 활성화한 로컬 서버에서만 허용됩니다.

```powershell
npm run validate:battle-rooms
npm run validate:battle-rooms-ui
npm run validate:room-spectators
npm run validate:room-spectators-ui
npm run build
```

브라우저 검증은 PC 3인 싱글 토너먼트와 모바일 가로 화면 4인 더블 리그를 사용합니다. 두 형식에서 실제 HTTP와 배틀 엔진으로 양쪽의 기술 사용 및 PP 감소를 확인하고, 나머지 대진은 실제 기권 명령으로 종료하여 대회 진행·결과·삭제를 검사합니다. 테스트용 결과 응답으로 경기 상태를 대체하지 않습니다.

관전 전용 검증은 서버 접근 권한·공개 정보 제한·중복 연출 생략을 확인하고, 실제 로컬 HTTP 서버와 브라우저에서 부전승 및 먼저 종료한 참가자의 관전, 양쪽 스프라이트와 실제 턴 연출, 관전 중 행동 요청 차단, 복귀와 다음 경기 자동 전환을 검사합니다.

`codex/battle-factory` 브랜치는 `vercel.json`에서 자동 배포가 꺼져 있으며 운영 배포는 `main`으로 진행합니다. 사용자가 승인한 대전방 배포에 이어 2026-09-13 관전 기능 커밋 `fd35770`을 운영에 반영했습니다. Vercel 배포 `dpl_w4iEzXQtRCZAaHxtkmBi2Txejbbs`의 Production Ready 상태와 `pokemon-champions-area-web.co.kr` 연결을 확인했습니다. 대전방 데이터는 기존 서버 전용 문서 저장소를 사용하므로 별도 DB 마이그레이션은 없습니다.

운영 검증은 `scripts/validateDeployedBattleRooms.mjs`로 새 익명 계정 세 개만 생성하여 실행했습니다. 싱글 토너먼트·더블 리그전에서 비밀번호와 방장 권한 검사, 출전 선택, 서버의 실제 턴 처리, 기권, 최종 순위와 방 삭제를 통과했습니다. 별도 3인 토너먼트에서는 부전승 참가자의 선출 중 관전, 실제 턴과 양측 공개 상태, 중복 연출 생략, 자신의 결승 출전 우선 전환, 탈락자의 결승 관전과 종료 후 스트림 해제를 확인했습니다. 레이팅 경기 수·추가 VP·사용률 기록이 증가하지 않았으며 테스트용 SQL 행 26개와 익명 계정 3개를 모두 정리했습니다. 상세 실행 기록은 Git에서 제외된 `scripts/.cache/room-live-validation/`에 있습니다.

검증 스크립트는 운영에 테스트 데이터를 만드는 명시적인 실행 도구입니다. Vercel Production의 커밋과 Ready 상태를 먼저 확인하고 `--confirm-production`, `--url`, `--expected-commit`, `--expected-css`를 지정해야 합니다. 확인된 신규 계정과 이 계정들이 만든 비밀번호 방만 사용하고 정리하며, 관전 대상도 이 실행에서 생성한 경기로 제한합니다. 필요한 서버 연결 정보는 Git에서 제외된 `.env.storage.local`에서 읽습니다.

대전방 홍보 영상과 재생성 절차는 [`promo/rooms/README.md`](../promo/rooms/README.md)에 정리했습니다.
