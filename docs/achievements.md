# 업적과 보상

현재 카탈로그는 **273개 업적**으로 구성됩니다. 일반 업적 35개와 AI 트레이너 238명 각각의 첫 승리 업적이 있으며, 전체 업적 보상 합계는 **44,800 VP**입니다. 업적은 계정별로 한 번씩 달성하고 보상을 받습니다.

로비의 **업적** 메뉴에서 조건, 진행도, 보상, 달성일을 확인할 수 있습니다. 승리 기록·배틀 도전·기믹 마스터·무대 정복·대회 업적·AI 첫 승리 분류와 검색, 달성 상태 필터를 제공합니다.

| 대표 조건 | 업적 보상 |
| --- | ---: |
| AI 트레이너별 최초 1회 승리 | 각 100 VP |
| 첫 승리 / 누적 10·50·100승 | 200 / 300 / 700 / 1,200 VP |
| 한 번도 기절하지 않고 승리 / 기믹 없이 승리 | 각각 200 VP |
| 기절과 기믹 사용 모두 없이 승리 | 500 VP |
| 5턴 이내 승리 / 지닌 도구 없이 출전해 승리 | 각각 300 VP |
| 3마리 이상으로 시작해 마지막 1마리만 남기고 승리 | 300 VP |
| 3마리 이상이 같은 타입 하나를 공유하는 팀으로 승리 | 400 VP |
| 메가진화·Z기술·다이맥스·테라스탈·원시회귀 사용 후 승리 | 기믹별 300 VP |
| 하드 난이도 승리 / 하드 상대 강화 +3단계 승리 | 400 / 500 VP |
| 3·5·10연승 | 300 / 600 / 1,000 VP |
| 리그 우승 / 토너먼트 우승 / 리그 7경기 전승 우승 | 1,000 / 800 / 1,500 VP |

기절 없는 승리와 기믹 없는 승리의 10회 누적, 서로 다른 AI 5·25·100명 및 전체 제패, 지역·무대 탐방 업적도 포함됩니다. 정확한 목록과 보상은 `src/data/achievementData.js`의 `ACHIEVEMENTS`가 기준입니다.

## 판정과 지급

배틀이 실제로 완료되면 조건에 맞는 업적을 한꺼번에 판정하고 **보상을 자동 지급**합니다. 여러 업적을 동시에 달성하면 각 보상을 합산하며, 기존 배틀 승리 보상과 업적 보상은 결과 화면에서 구분해 표시합니다. 추가 수령 버튼은 필요하지 않습니다.

- `battleEngine.js`의 `achievementFacts`를 사용하며 번역된 배틀 로그 문구로 판정하지 않습니다.
- 기절 횟수는 배틀 중 누적합니다. 회생의기도로 부활해 마지막에 전원이 살아 있어도 무기절 승리로 인정하지 않습니다. 같은 기절을 중복 계산하지 않으며, 부활 후 다시 기절하면 추가 계산합니다.
- 도구와 팀 타입은 출전 당시 정보를 보존합니다. 도구 소비·교환, 테라스탈, 폼 변화가 원래 출전 조건을 바꾸지 않습니다.
- 기믹은 실제 발동 기록을 사용합니다. 차단되어 발동하지 않은 요청은 제외하고, 종료된 다이맥스나 기믹 폼으로 시작한 포켓몬도 사용 기록에 반영합니다. 원시 폼으로 시작한 경우도 기믹 없는 승리 대상에서 제외합니다.
- AI 첫 승리는 이름 대신 카탈로그의 트레이너 ID로 구분합니다. 패배·무승부·기권은 연승을 종료합니다. 리그는 마지막 경기에서 패배해도 최종 순위가 우승이면 리그 우승 업적을 달성할 수 있습니다.
- 기존 누적 전적을 역산해 업적을 소급 지급하지 않습니다. 도입 후 구조화된 완료 정보가 기록되는 배틀부터 집계하며, 진행 중이거나 필수 판정 정보가 없는 결과에는 승리 업적을 지급하지 않습니다.

## 저장과 계정 동기화

`champions-achievements-v1`에 업적 진행도, 달성 기록, 최근 처리한 배틀 ID와 `walletBalance`를 함께 저장합니다. 이 데이터가 VP 잔액의 기준이며, **업적 달성과 증가한 잔액을 한 번의 로컬 저장으로 반영**합니다. 기존 `champions-vp-v1` 키는 호환용 잔액 사본입니다. 두 저장 사이에 새로고침이 발생해도 기준 데이터에서 업적과 잔액을 함께 복원합니다.

동일 결과 재처리는 배틀 ID와 현재 결과 정산 상태로 차단하고, 이미 달성한 업적은 다시 보상하지 않습니다. 로컬 저장 실패 시 지급 완료 상태로 진행하지 않고 재시도 안내를 표시합니다.

업적 저장 키는 기존 `PLAYER_STORAGE_KEYS`에 포함되어 계정 데이터 내보내기·교체·클라우드 동기화에 함께 전달됩니다. 계정을 바꾸면 해당 계정의 업적 데이터로 교체됩니다. 원자적 저장의 범위는 위 로컬 데이터 한 건이며, 클라우드는 기존 계정 저장 절차를 사용합니다.

## 검증

```powershell
npm run validate:achievements
```

이 명령은 실제 배틀의 누적 기절·부활·기믹·초기 도구 판정, 업적 조건과 보상 합산·중복 방지, 저장 실패와 잔액 복원, 계정 데이터 교체를 검증합니다.

브라우저 통합 검증은 `npm run validate:achievements-ui`로 실행합니다. 기존 `promo` 패키지의 Playwright와 Chromium이 필요합니다 (`npm --prefix promo install`, `npx --prefix promo playwright install chromium`). 별도 런타임의 Playwright를 사용하면 `ACHIEVEMENT_PLAYWRIGHT_MODULE` 환경 변수에 모듈 경로를 지정할 수 있습니다.

통합 검증은 5185 포트의 임시 Vite 서버와 격리된 브라우저 저장소를 사용하며 실제 계정에는 접속하지 않습니다. HTTP 응답에만 테스트용 제어 함수를 주입해 실제 배틀 완료 콜백, 보상 합산과 중복 방지, 새로고침 및 VP 사용 후 잔액, 저장 실패 재시도 시 AI 경기 결과 유지, 데스크톱과 모바일 가로 화면을 검사합니다. 화면 캡처는 Git에서 제외된 `scripts/.cache/achievement-ui/`에 저장합니다. 배포 전에는 `npm run build`도 실행합니다.
