# 포켓몬 사용률

로비의 **업적 바로 아래 → 포켓몬 사용률**, 또는 **설정 → 사용률**에서 확인한다. AI 대전 / 레이팅 배틀 두 탭과 싱글 / 더블 필터를 제공하며, 각 분류의 1~100위를 20마리씩 표시한다. 이름·타입·도감 번호 검색은 상위 100위 안에서 원래 순위를 유지한다.

필터 오른쪽의 **TOP 3 접기 / 펼치기** 버튼으로 상위 카드를 위아래로 접고 펼친다. 접으면 비워진 높이를 아래 세부 순위 목록이 채우고, 펼치면 그 높이만큼 목록이 줄어든다. 검색·현재 페이지·목록 위치와 대전 분류는 토글로 초기화하지 않는다. 접힘 선택은 기기 로컬 저장소에 유지하며, 저장된 선택이 없으면 낮은 가로 화면에서는 기본으로 접는다. 모바일 가로 화면에서 펼친 TOP 3는 이름·이미지·사용률을 압축 표시하며, 타입과 장착 아이템은 아래 세부 순위에서 확인한다.

## 집계 기준

- 이 게임에서 **배틀이 시작될 때 확정된 출전팀**을 집계한다. 공식 포켓몬 게임의 외부 통계가 아니다.
- 사용률 = 해당 포켓몬을 포함한 출전팀 수 ÷ 해당 분류의 전체 출전팀 수 × 100. 한 팀에 여러 포켓몬이 있으므로 사용률의 합계는 100%를 넘을 수 있다.
- AI 대전은 유저 팀만, 레이팅은 양쪽 인간 플레이어의 선출 팀을 집계한다. 미선출 후보, AI 상대팀, 매칭 대기·선출 중 취소는 제외한다. 시작 후 기권은 이미 참가한 팀으로 남는다.
- 같은 팀에서 같은 전국도감 번호는 한 번만 센다. 이로치·스킨·메가진화·다른 폼은 기본 전국도감 종으로 합친다.
- 누적 사용팀 수 내림차순, 동률은 전국도감 번호 오름차순이다. 순위 변화와 `%p`는 **해당 분류의 직전 집계가 반영되기 전 표본**과 비교한다. 직전 사용팀 수가 0이면 `NEW`다.
- AI는 인증된 플레이 기기에서 제출한 참가 기록이다. AI 엔진은 브라우저에서 실행되므로 서버가 전투 자체를 검증하는 통계는 아니다. 레이팅은 서버의 양쪽 선출 확정 트랜잭션에서 기록한다.

## 포켓몬별 아이템 TOP 3와 장착 추천

사용률 표의 포켓몬 이름 오른쪽에 해당 분류의 인기 아이템 1~3위를 아이콘·이름·사용률로 표시한다. 아이템 사용률은 **그 도구를 장착한 출전 횟수 ÷ 해당 포켓몬의 아이템 정보가 기록된 출전 횟수 × 100**이다. 무장착 출전은 분모에 포함하고, 아이템 정보가 없던 구버전 기록은 제외한다. 같은 종의 다른 폼이 한 팀에 출전했다면 아이템 정보는 각 개체마다 센다. 도구를 소비하거나 교체하기 전, 배틀 시작 시점의 장착을 기록한다.

박스 → 포켓몬 선택 → 지닌 도구에서는 네 분류의 횟수를 합산한 인기 TOP 3를 검색·분류 위에 고정한다. 추천 도구는 보유 목록에서도 항상 먼저 표시하며, 검색과 분류 조건은 그대로 적용한다. 미보유 도구와 다른 포켓몬이 사용하는 도구는 추천되어도 장착할 수 없다. 미획득 희귀 도구는 사용률 표에서 `?`로 표시하고 장착 추천에서는 제외한다. 기록이 없으면 임의 추천을 만들지 않는다.

## 로컬 플레이 테스트

```powershell
npm run usage:test
```

`http://127.0.0.1:5186`에 로그인 없이 사용할 수 있는 별도 테스트 파티가 열린다. Firebase 인증은 테스트 실행에서 대체되며 운영 계정에 접근하지 않는다. 팀 1·2를 편성해 두었고 나머지 팀도 게임의 박스에서 구성할 수 있다.

각 분류는 **임의 표본 없이 0팀**으로 시작한다. 화면과 아이템 추천에는 **로컬 플레이 집계**가 표시된다. AI 대전을 시작하면 해당 분류에 1팀, 두 창에서 테스트 트레이너 A/B로 레이팅 선출을 마치면 2팀이 추가된다. 사용률 창을 다시 열거나 새로고침 버튼을 눌러 수치·순위 변화를 확인한다. 실제 로컬 플레이 기록만 `scripts/.cache/pokemon-usage-live-test/state.json`에 유지되며 종료는 `Ctrl+C`다. 이전 임의 표본 저장소는 읽거나 자동 이전하지 않는다.

아이템 기록도 처음에는 비어 있으며 실제로 선택한 출전 포켓몬의 장착 정보만 누적한다. 기록이 없으면 추천도 비어 있다. 플레이 준비를 위한 테스트 파티와 일반 도구는 별도 로컬 인벤토리에 제공하며 통계에는 자동 반영하지 않는다. 새 테스트 파티의 시작 VP는 게임의 `INITIAL_VP_BALANCE`를 그대로 사용한다.

이 명령은 로컬 서버 `8788`과 웹 `5186` 포트만 사용한다. `.env`나 운영 설정을 변경하지 않는다. 통합 검증은 별도 메모리 저장소를 사용하므로 위 수동 테스트 기록도 바꾸지 않는다.

```powershell
npm run validate:pokemon-usage
npm run validate:pokemon-usage-ui
node scripts/validatePokemonUsageUi.mjs --layout-only
node scripts/validatePokemonUsageUi.mjs --fresh
npm run build
```

자동 검증용 예시 통계는 `scripts/fixtures/pokemonUsageDemo.mjs`에만 있으며 운영 모델·서버와 수동 테스트 실행기에서 가져오지 않는다. 기존 UI 회귀 검증은 100위 전체·변동·상위 도구를 비교하기 위해 이 예시를 격리된 메모리 저장소에 넣고 `VITE_POKEMON_USAGE_SEEDED_TEST=true`로 명확히 표시한다. `--fresh` 검증은 이 플래그와 예시 주입을 끄고 빈 DB에서 실제 AI 대전 → 1팀 및 최초 아이템 추천 생성, 실제 싱글/더블 레이팅 → 각각 2팀을 확인한다.

`VITE_POKEMON_USAGE_DEMO`와 기존 `isPokemonUsageDemo`는 이름과 달리 예시 통계 생성기가 아닌 **개발 모드·브라우저/서버 모두 loopback·레이팅 로컬 테스트**의 인증 우회 및 테스트 앱 진입 경계다. `demo` 통계 라벨은 이 경계를 모두 통과하고 별도 seeded-test 플래그까지 있을 때만 사용한다. 일반 로컬은 `local`, 운영은 항상 `live`이며 재전송 대기열도 세 출처별로 분리한다.

## 저장·공개 경계

기존 인증 API의 `GET /api/ranked?action=usage`는 공개 가능한 네 분류의 집계만 반환한다. 닉네임·계정 ID·개별 파티·배틀 로그는 반환하지 않는다. 화면 진입·명시적 새로고침 때 읽으며 순위 조회를 주기적으로 폴링하지 않는다.

`POST action=reportAiUsage`는 안정적인 `battleId`, `format`, 실제 `speciesIds`, `team: [{ speciesId, heldItemId }]`를 사용한다. 무장착은 `heldItemId: null`로 전송한다. UID는 인증에서 가져오고, UID + battleId의 해시로 영구 중복 방지 영수증을 저장한다. 같은 ID의 다른 파티·분류·아이템 재전송은 거절한다. 전송 대기 기록은 계정별 로컬 저장소에 먼저 보관하며 재접속·온라인 복구·재시도 때 동일 ID로 보낸다. 구버전 대기 기록도 중복 없이 이어서 반영한다. 저장 자체가 실패하면 게임 진행은 계속하되 해당 경기의 통계 누락을 알린다.

운영 연결은 클라이언트 `VITE_POKEMON_USAGE_ENABLED=true`, 서버 `POKEMON_USAGE_ENABLED=true`를 함께 설정한다. 운영 Firestore의 기존 실제 기록만 읽고, 기록이 없으면 0팀으로 반환한다. 예시 표본 생성·과거 참가 기록 추정·아이템 분포 보정은 하지 않는다. 기존 Firestore를 사용하며 새 유료 서비스는 추가하지 않는다. 집계 읽기·쓰기 역시 기존 서비스 할당량을 사용한다.
