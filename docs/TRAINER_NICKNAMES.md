# 트레이너 닉네임

설정 → 계정 → 트레이너 닉네임에서 일반 Google 계정의 게임 표시 이름을 저장하거나 해제한다. 미설정 계정은 이름의 첫 글자와 `**`를 표시하며, 게스트는 기존 이름을 유지한다. Google 계정의 이름이나 이메일은 수정하지 않는다.

## 동작

- 닉네임은 NFKC 정규화·앞뒤 공백 제거 후 2~12자이며 한글, 영문, 숫자, 공백, `_`, `-`를 허용한다. 빈 문자열은 해제를 뜻한다.
- 서버에서 욕설·비속어, 보이지 않는 한글 채움 문자, 예약된 `guest-000000` 형식을 거부한다. 일반 닉네임 사이의 중복은 허용한다.
- 서버 저장이 확인된 후에만 상단바와 계정 카드의 표시 이름을 변경한다. 실패 시 기존 이름과 입력 초안을 유지한다. 계정 전환 뒤 도착한 옛 계정의 응답은 적용하지 않는다.
- 프로필을 로그인 시 불러오므로 새로고침·재로그인·다른 기기에서도 유지된다. 게스트는 편집 UI가 없고 직접 API 요청도 거절된다.
- 채팅의 새 메시지, 대전방 명단과 이후 배틀, 레이팅·팩토리 랭킹에 공개 닉네임을 사용한다. 랭킹 조회 시 자신의 기존 기록은 표시 이름만 갱신하며 점수·층수·기록 시각·팀은 유지한다.
- 이미 진행하거나 종료한 배틀의 로그와 과거 채팅 메시지는 당시 이름을 유지한다. AI 대회 및 팩토리 배틀은 시작할 때의 공개 이름을 사용한다.

## 저장과 공개 정보

`/api/account`의 `setNickname`은 인증된 UID와 활성 세션의 `ownerId`로 `account/profiles/{uid}.nickname`을 갱신한다. `ensureProfile`은 닉네임을 보존하며 인증 제공자의 메타데이터만 갱신한다. 일반 게임 저장 payload에 닉네임을 넣어 다른 기기의 오래된 저장으로 덮어쓰지 않는다.

공개 API는 요청 본문의 닉네임을 신뢰하지 않고 서버 프로필에서 가져온 `identity.nickname`만 사용한다. 표시 함수는 명시된 공개 닉네임만 마스킹에서 제외한다. 같은 실제 이름을 가진 트레이너나 다른 트레이너의 실제 이름과 같은 닉네임이 있어도 미설정 계정의 이름을 공개하지 않는다.

일반 공개 조회의 닉네임 확인은 15초 캐시와 동시 조회 병합을 사용하며 캐시는 2,000개로 제한한다. 채팅 전송·매칭 참가·방 생성/참가·팩토리 기록·랭킹 명시 조회는 최신 프로필을 확인한다. 계정 저장·세션 heartbeat와 게스트 인증에는 추가 닉네임 조회를 하지 않는다. 새 테이블·환경변수·DB 마이그레이션은 필요 없다.

## 검증

```powershell
npm run validate:trainer-nicknames
npm run validate:trainer-nicknames-ui
node scripts/validateBattleFactoryRankingClient.mjs
npm run build
```

서버 저장/검증, 프로덕션 인증과 캐시, 기본 마스킹·공개 닉네임 전파·게스트·이름 충돌·위조 요청, 실제 AuthProvider의 비동기 계정 경계, 실제 SettingsModal과 GameApp을 확인한다. UI는 PC/모바일 가로의 글씨 1배·2배를 포함한다. 검증은 로컬에서 수행하고 실제 사용자의 닉네임이나 운영 채팅을 변경하지 않는다.

브라우저 검사 결과와 캡처는 Git에서 제외되는 `scripts/.cache/trainer-nickname-ui/` 및 `scripts/.cache/trainer-nickname-auth/`에 저장한다.
