# 더블배틀 대상 및 교체 선택 수정

## 대상이 먼저 쓰러진 뒤의 공격

UI에서 상대 진영과 슬롯을 명시한 행동은 실행 직전 대상 검증에서 기절한 포켓몬을 거절하고 종료했다. 그래서 같은 적을 두 포켓몬이 공격할 때 첫 공격으로 적이 쓰러지면 두 번째 공격은 자동 재지정에 도달하지 못했다.

현대 배틀 규칙에 따라 상대가 기절해 비어 있는 슬롯을 향한 단일 공격은 같은 상대 진영의 합법적인 대상에게 재지정한다. 트리플배틀에서는 인접 범위를 지키고 여러 후보가 있으면 난수로 선택한다. 같은 슬롯에서 교체된 포켓몬, 방어·일시 무적·타입 면역을 가진 살아 있는 상대는 기존 대상을 유지한다. 사령탑으로 숨은 싸리용도 단순한 빈 슬롯과 구분한다. 연속 공격의 타격들을 서로 다른 상대에게 분배하지 않는다.

아군을 겨냥한 기술은 일반적인 상대 재지정 규칙을 적용하지 않는다. 아군 또는 자신을 대상으로 하는 기술의 개별 예외는 별도로 검사한다. 대상이 없는 실패도 해당 사용의 PP와 실패 기록을 정확히 처리한다.

원본 비교: [Showdown getTarget/getRandomTarget](https://github.com/smogon/pokemon-showdown/blob/master/sim/battle.ts), [대상 목록과 인접 판정](https://github.com/smogon/pokemon-showdown/blob/master/sim/pokemon.ts), [충전·사령탑 상태](https://github.com/smogon/pokemon-showdown/blob/master/data/conditions.ts).

## 교체 선택 반복

첫 아군의 교체를 예약하면 `submitPlayerAction`이 다음 아군의 기술 메뉴를 선택하지만, `chooseSwitch`의 마지막 `setMenu('command')`가 이를 덮어썼다. 사용자가 다시 메뉴를 열면 예약을 초기화하면서 첫 슬롯으로 돌아갔다.

다음 명령 화면은 `submitPlayerAction`이 결정하도록 수정했다. 모든 아군의 행동을 정한 뒤 턴을 실행하며, 먼저 예약한 벤치 포켓몬에는 `교대 예약`을 표시해 다른 슬롯에서 중복 선택할 수 없게 했다. 전체 선택 취소, 강제 교체, 교대기 뒤의 중간 턴 재개는 각각 기존 흐름을 유지한다.

## 사용하지 않는 신고 기능 제거

설정의 신고 탭·입력 폼·클라이언트 요청·서버 API·Vite 미들웨어·관련 CSS 및 전용 검증/운영 문서를 제거했다. 설정은 게임·오디오·업적·계정 네 탭으로 구성된다. 로컬과 Vercel의 전용 메일 환경 설정도 제거했다. 로컬 신고 API의 POST 응답은 404이며 실제 이메일을 발송하는 검증은 하지 않았다.

## 검증

```powershell
npm run validate:battle-retargeting
npm run validate:double-battle-commands-ui
npm run validate:battle-audit
npm run validate:battle-pivots-ui
npm run build
```

검사는 합법적인 포켓몬·기술 조합과 실제 BattleScreen의 버튼 선택, 행동 예약, HP·PP·턴 번호·타임라인을 사용한다. 전체 실행 검사는 모든 기술·특성·도구 조합의 완전 탐색을 의미하지 않는다.

- 대상 재지정 20개: 양 진영·양 슬롯, 변경된 타임라인 대상, 교체된 상대, 방어·면역·공중·사령탑, 트리플 인접/무작위 후보, 기절한 아군, 충전 기술·프리폴, 연속 공격을 통과했다.
- 실제 PC/터치 모바일 UI 16개: 양 슬롯 교체, 중복 예약 차단, 취소, 연속 클릭, 다음 턴, 점사, 설정 탭 제거를 통과했다. 점사 사례는 엔진 수정 완료 후 새 서버에서 두 기기 모두 재검증했다.
- 기존 교대기/회생 UI 14개를 통과했다.
- 전체 `validate:battle-audit`를 통과했다. 상태 검사에서는 기술 847개(2,541개 사례), 사용 가능한 특성 313개(626개 사례), 총 14,357턴의 HP·PP·능력치·교체·입력 불변성을 확인했다. 기존 광역기·교대기·풍선·기믹 타이밍 검사도 통과했다.
- 프로덕션 빌드를 통과했다. 기존 큰 번들 크기 경고는 남아 있다.
